Factionlog

A Standard Notation for Open Strategy Game Session Logging

Author

Roberto Bisceglie

1. Introduction

1.1 Why Factionlog?

The Referee’s job doesn’t end when the dice drop. Every adjudication needs to be recorded with enough structure to be traceable: what the faction argued, why their leverage was graded the way it was, what the dice produced, and what changed in the world as a result. The Report is the public face of this work. The session log is the working record behind it.

Free-form notes lose the mechanics. A raw dice log loses the leverage argument. A pure narrative loses the board state. Factionlog offers a different approach: a compact shorthand that captures the essential elements of OSG play (the three-part action argument, the leverage grade, the adjudication, and the consequences) in a format that is fast to write, easy to review, and legible to anyone who knows the system.

1.2 What Factionlog Does

For live tables, asynchronous campaigns, solo games and archived records, this notation helps you:

  • Record every faction’s three-part action (act / out / lev) in a consistent structure
  • Document the leverage grade and dice result for every adjudicated action
  • Track faction positions, spendable bonuses, and board-state changes across turns
  • Write Reports that are grounded in and traceable to the session log
  • Share the complete game record with players who will understand the format at a glance

The notation is designed to be:

  • Compact: the argument is structured, not verbose
  • Traceable: every outcome points back to the leverage argument that produced it
  • Format-agnostic: works in digital markdown or paper notebooks
  • Extensible: optional layers for persistent tracking and solo play

1.3 How to Use This Notation

Four elements mirror the natural flow of OSG adjudication:

  • @(Faction) for each faction’s submitted action (three-part argument)
  • d: for the roll: leverage grade, dice, kept die, and the verdict after ->
  • => for what the outcome changes in the world
  • the Report block, between \--- and ---\, for the public summary

That’s the core. Everything else (faction tags, bonus tracking, location markers, clocks) is optional. Add it when the game’s complexity requires it.

1.4 Quick Start: One Turn

@(Meranto)
  act: Send the debt review notice to Caldrath's treasury
  out: Delay Caldrath's army movement for thirty days
  lev: We hold all loan documentation; the emergency clause has precedent
d: Strong 2d6kh1[5,3]=5 -> Success
=> Caldrath's treasury enters review, but the scope of the review is disputed

@(Caldrath)
  act: Deploy advance units to Essaveth's northern pass
  out: Establish a military presence before any treaty negotiation
  lev: Largest army on the peninsula, camped at the foot of the passes
d: Strong 2d6kh1[6,2]=6 -> Success, and...
=> Essaveth's border garrison stands down without resistance
[Fac:Caldrath|pos:pass occupied]

\---
Meranto's auditors are in Caldrath's treasury. Caldrath's army is in
Essaveth's pass. The Conclave has issued no statement.
---\

That is a full turn. Everything else in this document handles complexity when you need it.

1.5 Factionlog and Lonelog

Factionlog is a fork of Lonelog, a notation system for solo RPG session logging, and follows Lonelog v1.7. Lonelog’s core philosophy (separate mechanics from fiction, stay compact, scale from one-shots to campaigns) carries directly into OSG play. The symbols, the d: line, the tag system, progress tags, meta notes and long blocks are shared.

Factionlog changes three things to fit OSG’s model of faction-scale play, simultaneous submission, and the three-part argument:

  • Actions are always attributed: @(Faction). In solo play, a bare @ may stand for your own faction.
  • Each action carries an argument on three indented lines: act:, out:, lev:.
  • The d: line uses the leverage grade as its label, and its verdicts are OSG’s four result bands.

If you know Lonelog, you’ll feel at home. If you don’t, this document is fully standalone.

2. Digital vs. Analog Formats

2.1 Digital Format (Markdown)

In digital markdown files:

  • Campaign metadata: YAML front matter, top of file
  • Campaign title: level-1 heading
  • Sessions: level-2 headings (## Session 1)
  • Turns: level-3 headings (### Turn 1)
  • Core notation and tracking: inside code blocks
  • Commentary: regular prose between code blocks

Note: Always wrap notation in code blocks when using digital markdown. This prevents conflicts with Markdown syntax and ensures symbols like => render correctly.

2.2 Analog Format (Notebooks)

In paper notebooks:

  • Write headers and metadata directly as shown
  • Write each turn header on its own line: Turn 1
  • Core notation works identically but without code fences
  • Brackets and tags help scanning paper pages

2.3 Indentation

Indentation carries no meaning, except under a tbl: line, where indented lines are the table’s entries. Indent the act:, out: and lev: lines, and the continuation lines of a long argument, because it makes the log easier to read.

2.4 Format Examples

Digital:

## Session 1
Date: 2026-05-01 | Turns: 1–2

### Turn 1
@(Meranto)
  act: File a debt review against Caldrath's treasury
  out: Delay army movement thirty days
  lev: Emergency clause, full documentation, precedent established
d: Strong 2d6kh1[6,2]=6 -> Success, and...
=> The army is held at the border
[Fac:Caldrath|pos:army held at border]
[Clock:Liquidity Review 1/3]

Analog:

Turn 1

@(Meranto)
  act: File a debt review against Caldrath's treasury
  out: Delay army movement thirty days
  lev: Emergency clause, full documentation, precedent established
d: Strong 2d6kh1[6,2]=6 -> Success, and...
=> The army is held at the border
[Fac:Caldrath|pos:army held at border]
[Clock:Liquidity Review 1/3]

Both formats use identical notation; only the wrapping differs.

3. Core Notation

This is the heart of the system. The elements mirror the natural flow of OSG adjudication: the faction argues its action, the Referee grades leverage, the dice give a verdict, and the board changes.

Where symbols go. In the standard form, each element (@(…), ?, d:, tbl:, ->, =>) starts its own line, as in the examples below. In the compact form, elements follow one another on one line, each symbol preceded by a space. Compact form suits fast play (§3.6).

3.1 Faction Actions (@(Faction))

@(Faction) records a faction submitting its turn action. Every action in OSG follows the same three-part structure:

@(FactionName)
  act: What specifically are they doing?
  out: What result do they want?
  lev: Why is this action likely to produce that outcome?

The three sub-lines are not optional decoration. They are the argument the Referee adjudicates. act commits the faction to a specific course of conduct. out separates what they are doing from what they want: the Referee adjudicates the outcome, not just the action. lev is the case for why the plan should work, grounded in established fiction: resources, relationships, positioning, prior actions.

Example: full argument:

@(Meranto)
  act: Send formal notice of debt review to Caldrath's treasury,
       citing the emergency clause in our lending agreements
  out: Delay Caldrath's army movement by forcing a liquidity
       assessment before any major campaign expenditure
  lev: Caldrath's military expansion was financed by Meranto loans.
       The emergency clause exists, has precedent, and their treasury
       minister knows invoking it freezes discretionary spending for
       thirty days. We hold documentation for every transaction.

Example: compact (fast play):

@(Meranto)
  act: Invoke emergency debt clause against Caldrath
  out: Freeze army expenditure for one turn
  lev: Full documentation; clause has precedent

Both are valid. Use the level of detail the game requires.

3.1.1 Joint Actions (@(A+B))

When two or more factions pool their turns into one joint action, name them all, joined by +. The lev: line names each participant’s contribution:

@(Meranto+Essaveth)
  act: Close the passes to Caldrath's supply trains and freeze
       its credit in the same week
  out: Caldrath's army cannot provision a march on Corenth
  lev: Essaveth holds the passes; Meranto holds Caldrath's loans

Lonelog’s Lead/Assist form @(A > B) is not used: an OSG faction either spends its action or does not.

3.1.2 Spendable Bonuses in the Argument

If an action spends a named bonus, record the spend inside the leverage line, with a [Bon:] tag update (§4.1.2):

@(Saivorn)
  act: Rush naval assets to the Corenth harbour mouth
  out: Establish a naval blockade before Caldrath can resupply
  lev: Two deep-water ports give unmatched transit speed;
       treaty access to Corenth's outer anchorage invoked
       [Bon:Saivorn|Harbour Rights-1]

The bonus ticks down at the point of use, visible in the leverage argument where it matters for adjudication.

3.2 The Roll (d:)

The d: line records the adjudication: the leverage grade, the dice, the kept die, and the verdict.

d: <Grade> <dice>[<die results>]=<kept> -> <verdict>
d: Strong 2d6kh1[5,3]=5 -> Success
d: Weak 2d6kl1[5,3]=3 -> Worse

The grade is the label. Strong leverage keeps the highest die (2d6kh1); Weak keeps the lowest (2d6kl1). Strong means the faction has enough established advantage (resources, relationships, positioning, prior actions) that success is more likely than not. Weak means the attempt is plausible but without a strong basis. The Referee is not scoring a debate: the grade is a qualitative judgment following from the argument and the established fiction.

The verdict follows -> on the same line:

Kept die Verdict Code Meaning
6 Success, and... Sa Desired outcome; something especially good may also occur
4–5 Success S Desired outcome occurs
2–3 Worse W Action proceeds, but the outcome is worse than desired
1 Worse, and... Wa Worse than desired; something especially bad may occur

Roll context. When something specific is active for this roll, such as a bonus, list it before the dice, as Lonelog does: d: Strong +[Debt Clause] 2d6kh1[4,6]=6 -> Success, and....

Unopposed actions have no roll. Record the rule that decided them:

d: Unopposed -> Success

Actions in conflict. When two actions oppose each other directly, record each roll, then the comparison:

@(Essaveth)
...
d: Strong 2d6kh1[3,5]=5 -> Success

@(Caldrath)
...
d: Strong 2d6kh1[4,4]=4 -> Success

d: Conflict Essaveth 5 vs Caldrath 4 -> Essaveth prevails
=> Caldrath's outcome is worse than desired: the gates stay shut

On a tie: -> Standoff.

3.2.1 Force of Nature (Doubles)

When both dice show the same number, the Referee may introduce a Force of Nature: a chaotic event outside any faction’s control. The die results in brackets show the doubles. Mark the event with an event tag:

d: Strong 2d6kh1[3,3]=3 -> Worse
[E:Harbour Storm|Force of Nature]
=> All sea transit actions are opposed next turn
=> Saivorn's naval advantage is temporarily neutralized

The Force of Nature is a prompt, not a requirement. Use it only when it fits the fiction and creates genuine complications, at most once or twice per game.

3.3 Consequences (=>)

The => symbol records what the outcome means in the world: what happened, what changed, and what other factions must now contend with. The verdict on the d: line says how well it went; the => lines say what that looks like.

d: Strong 2d6kh1[5,3]=5 -> Success
=> The review opens, but its scope is disputed
=> Caldrath's chancellor publicly accuses Meranto of bad faith
[Fac:Meranto|pos:diplomatically exposed in Corenth]

Chain multiple => lines for cascading effects. Every outcome should pass the RAT check: Reasonable (proportionate to the fiction), Actionable (leaves something for other factions to respond to), and Traceable (points to earlier events). If it fails any of these, rewrite it before moving on.

3.4 The Report Block (\--- … ---\)

At the end of each turn, the Referee publishes a public Report. Record it as a long block, between a \--- line and a ---\ line, immediately after the turn’s adjudications:

\---
Meranto's debt clause stalls Caldrath's army at the border.
Saivorn's diplomatic overture is rebuffed, and Caldrath now
knows of it. Essaveth has gone quiet. The Conclave has summoned
representatives from all factions to the temple complex.
Next turn, the question is who arrives first.
---\

The Report is public fiction; everything inside the block is known to all factions. Private outcomes are logged only in => lines inside the relevant faction’s entry.

3.5 Questions and Tables (?, tbl:)

? asks a question that the fiction has not settled, and tbl: records random content. A Referee uses them for world questions; a solo player uses them constantly (§7).

? Are the mercenary companies still for hire? (Likely)
d: 2d6kh1[2,5]=5 -> Yes
tbl: Mercenary Company (d6) [Grey Lances, Salt Brothers, Grey Lances, Salt Brothers, both, neither]
tbl: Mercenary Company d6=2 -> Salt Brothers

As in Lonelog: d: gives a verdict (did it work? is it so?), tbl: gives content (what? who?).

3.6 Compact Form

For fast play, chain the elements on one line:

@(Caldrath) act: advance on the pass out: occupy it lev: largest army d: Strong 2d6kh1[6,2]=6 -> Sa => garrison stands down

Use it for quick turns and minor factions. The full argument stays traceable; it is just shorter.

4. Optional Layers

4.1 Persistent Elements

Tags record state. They accumulate: a later tag for the same element adds to what is already known, without restating everything.

Write Effect
value Adds a value
-value Removes a value
old>new Replaces one value
category:value Replaces what the category held
category:+v / category:-v Adds or removes one entry in a category
Name N / Name+N / Name-N Sets or adjusts a number

A tag can span several lines: open with [Type:Name, put each | value on its own indented line, and close with ] on its own line.

4.1.1 Faction Tags ([Fac:])

Track faction state across turns. Establish at Turn Zero and update as the board changes.

[Fac:Meranto
  | obj:control Corenth debt leverage
  | pos:agents everywhere, no map token
]

Categories:

  • obj: the faction’s objectives (from the Brief; does not change)
  • pos: its current position on the board

Show only what changed:

[Fac:Caldrath|pos:army held at border]
[Fac:Caldrath|pos:army held at border>pass occupied]
[Fac:Saivorn|pos:+diplomatically exposed]

4.1.2 Spendable Bonuses ([Bon:])

The tag is named for the faction that owns the bonuses; each bonus is a labelled number of remaining uses.

[Bon:Meranto|Debt Clause 2|Emergency Recall 1]
[Bon:Meranto|Debt Clause-1]

A bonus should be contextually bounded: its narrative name indicates when it applies. A spent bonus cannot be recovered.

4.1.3 NPA Tags ([NPA:])

For Non-Player Actors controlled by the Referee, track objective, position, and behavior rule:

[NPA:Conclave|obj:Corenth remains neutral|pos:temple complex
  |behavior:mediates; escalates if the temple is threatened]

NPA actions use @(Name) notation identical to player faction actions. The Referee adjudicates them the same way.

4.1.4 Locations ([L:])

Mark significant locations and their current control state.

[L:Corenth|status:contested|Conclave extraterritorial temple]
[L:Northern Pass|control:Caldrath]
[L:Harbour Mouth|control:Saivorn]

4.1.5 Objectives ([Obj:])

Track each faction’s objectives from the Brief. An objective holds one state, changed with old>new.

[Obj:Control Corenth debt leverage|Open]
[Obj:Prevent Caldrath military presence|Open]
[Obj:Isolate Saivorn from Conclave|Open>Achieved]
[Obj:Preserve Meranto financial network|Open>Failed]

4.1.6 Events and Progress ([E:], [Clock:], [Track:], [Timer:])

An event tag marks something notable that happened, a turning point you will want to find again:

=> The Conclave summons every faction to Corenth [E:Conclave Summit Called]

Anything that builds up toward a result is a progress tag:

Tag Meaning
[Clock:Name X/Y] Fills up toward a threat
[Track:Name X/Y] Fills up toward a goal
[Timer:Name X] Counts down to zero
[Clock:Name+1] Advances a counter 
[Clock:Caldrath Liquidity 1/3]
[Track:Essaveth Guarantees 1/2]
[Timer:Conclave Summit 1]
[Clock:Caldrath Liquidity+1]

4.1.7 Threads ([Thread:])

A thread is an open hook from a Report: something unresolved that a faction may act on.

[Thread:Meranto agents near the garrison road|Open]
[Thread:Meranto agents near the garrison road|Open>Closed]

4.2 Turn Zero

Turn Zero is the pre-game clarification session. Log world assumptions, faction setups, and any rulings made before Turn 1 under a Turn 0 header. Record rulings as meta notes.

Turn 0

(ruling: unopposed actions succeed; the Referee still decides how
  they land, and every success reshapes the board)
(ruling: talking is free; only what a faction does costs its action)
(ruling: one action per faction per turn; two things in one action
  are returned for revision)
(ruling: Caldrath's army is camped at the foot of the northern
  passes at game start)
(ruling: Meranto has no physical presence on the map; leverage
  only, no tokens)

[Fac:Meranto
  | obj:control Corenth debt leverage
  | pos:agents everywhere, no map token
]
[Bon:Meranto|Debt Clause 2|Emergency Recall 1]
[NPA:Caldrath|obj:military dominance of Corenth|pos:army at the passes
  |behavior:aggressive; moves on Corenth if unopposed by Turn 3]
[NPA:Saivorn|obj:secure port access to Corenth|pos:coast, two ports
  |behavior:opportunistic if Caldrath is weakened]
[NPA:Essaveth|obj:preserve pass autonomy|pos:northern passes, small garrison
  |behavior:defensive; seeks alliance if threatened]
[NPA:Conclave|obj:Corenth remains neutral|pos:temple, extraterritorial
  |behavior:mediates; escalates if the temple is threatened]

4.3 Meta Notes

Step outside the fiction for rulings, design notes, and retrospective annotations. Use Lonelog’s labels: note:, house:, ruling:, interp:, retcon:, todo:, question:, reflection:, source:, break:.

(ruling: NPA behavior tables are rolled before each turn; results stay
  private until logged as actions)
(note: Turn 3 reconstructed from notes; dialogue is paraphrased)
(note: Caldrath player absent Turn 2; NPA holding action used)
(house: bonuses may be spent on Strong leverage to turn a 4–5 into a 6)

Corrections. Do not edit the log silently. Leave the original line and add a retcon: note after it:

d: Weak 2d6kl1[5,3]=3 -> Worse
(retcon: leverage should have been Strong: 2d6kh1 keeps 5, Success)

5. Optional Structure

5.1 Game Header

---
title: The Corentine Crisis
system: Open Strategy Game
notation: Factionlog 0.3.0
turns: 6
factions: Meranto, Caldrath, Saivorn, Essaveth, Conclave
date: 2026-05-01
---

5.2 Session Header

For multi-session games:

## Session 1
Date: 2026-05-01
Turns: 1–2
Recap: Turn Zero complete. Factions established.
       Caldrath is already moving.

5.3 Turn Headers

Each turn opens with a header: a level-3 heading in digital files, a plain line on paper. Add a short context in asterisks if it helps:

### Turn 3 *The Corenth summit*

5.4 Debrief

At game end, record each faction’s self-assessment under a Debrief header:

Debrief

Meranto: The Debt Clause delayed Caldrath two turns. The Conclave
  alliance failed. The financial network is intact.
[Obj:Control Corenth debt leverage|Open>Achieved]
[Obj:Prevent Caldrath military presence|Open>Partial]
[Obj:Preserve Meranto financial network|Open>Achieved]

6. Complete Turn Example

A full multi-faction turn from The Corentine Crisis, Turn 2.

Turn 2

@(Meranto)
  act: Approach Essaveth privately: offer to underwrite their
       garrison costs in exchange for pass access rights
  out: Establish a quiet alliance before Caldrath occupies the pass
  lev: Essaveth is under military pressure and has no defensive pact.
       Meranto holds their small infrastructure debt. Immediate
       financial relief, something Caldrath cannot match.
       [Bon:Meranto|Debt Clause-1]
d: Strong +[Debt Clause] 2d6kh1[4,6]=6 -> Success, and...
=> Essaveth accepts, and volunteers intelligence on Caldrath's
   supply line through the pass
=> Essaveth's public posture stays neutral; the alliance is secret
[Fac:Essaveth|pos:quiet Meranto ally]
[Bon:Essaveth|Intelligence File 1]
[Fac:Meranto|pos:pass access secured]

@(Caldrath)
  act: Send an envoy to Essaveth demanding right of passage for
       the army, framed as a treaty obligation
  out: Secure legal cover for army movement through the pass
  lev: Largest army on the peninsula; Essaveth owes historical
       obligations from the old compact; the army is already visible
       at the border, and the implicit threat needs no elaboration
d: Strong 2d6kh1[2,3]=3 -> Worse
=> Essaveth stalls, citing the need for Conclave ratification
   before any troop movement
=> Caldrath's envoy returns empty-handed, and it is publicly noted
[Fac:Caldrath|pos:army delayed at border]
[Clock:Pass Negotiation 1/3]

@(Conclave)
  act: Issue a formal invitation to all factions for a Corenth
       summit, citing the army movements as a threat to the
       neutral zone
  out: Establish itself as the legitimate mediating authority
       before any faction acts unilaterally in Corenth
  lev: Extraterritorial status; all factions have obligations
       under the old treaty; the neutral city gives the Conclave
       standing no other actor can claim
d: Strong 2d6kh1[3,5]=5 -> Success
=> All factions receive the invitation [E:Conclave Summit Called]
=> Every faction must now decide: attend, refuse, or act before it
[Timer:Conclave Summit 1]

\---
Caldrath's envoy returns from Essaveth without an answer.
The Conclave has summoned all factions to Corenth.
The summit will be held next turn. Essaveth has gone quiet.
Meranto's agents were seen near the northern pass.
The question now is who arrives in Corenth, and how.
---\

7. Solo Extension

When playing OSG solo (see Contested Ground: Solo Mode), the Referee role collapses into the player. Factionlog’s core notation works unchanged: every Autonomous Actor’s action is logged with @(Name) exactly like a player faction’s. You may write your own faction’s actions with a bare @, as Lonelog does for the primary character; naming it is clearer in a shared log. The additions below cover the solo procedures.

7.1 Oracle Questions (?)

Put the odds in parentheses at the end of the question. The roll and answer follow in any of Lonelog’s three forms:

? Are the mercenary companies still for hire? (Likely)
d: 2d6kh1[2,5]=5 -> Yes

? Does the road flood? (Even)
-> No, but... (d6=3)

? Does the Conclave know? (Unlikely)
-> Nb

Odds and rolls: (Likely) is 2d6kh1, (Even) is d6, (Unlikely) is 2d6kl1. The six answers and their codes:

Die Answer Code
6 Yes, and… Ya
5 Yes Y
4 Yes, but… Yb
3 No, but… Nb
2 No N
1 No, and… Na

When the grade itself is uncertain, ask about it:

? Is Caldrath's leverage Strong? (Even)
-> Yes (d6=5)

7.2 AA Tables (tbl:)

Define each AA’s Action Table once, at Turn Zero, with indented numbered entries:

tbl: Caldrath Action (d6)
  1: March a column through the northern passes toward Corenth
  2: Petition the Conclave to recognize the King as interim Arbiter
  3: Demand right of passage from [target], backed by the army
  4: Seize a depot, toll post or road held by [target]
  5: Hire one of the two mercenary companies
  6: Formally declare the claim on Essaveth's northern province

Log each roll as a result, with the target filled in:

tbl: Caldrath Action d6=3 -> Demand right of passage from Essaveth

An AA that holds, or acts on a deal obligation, rolls nothing. Say why in a note:

(note: Meranto holds: Schemer, even turn)
(note: Meranto acts on its deal with Essaveth instead of rolling)

Open questions, Signals, Secrets and Inspiration Tables are content, so they are tbl: too:

tbl: Which Faction (d6) [Caldrath, Meranto, Caldrath, Meranto, Caldrath, Meranto]
tbl: Which Faction d6=2 -> Meranto
tbl: Caldrath Signal d6=3 -> Warning
tbl: Especially Good d6=4 -> Weakens a rival

7.3 Rival Tags ([Rival:])

Use [Rival:] for AA state: objective, leverage, behavior rule and disposition toward you.

[Rival:Meranto|obj:turn two factions' debts into leverage|lev:economic
  |behavior:Schemer|disp:Neutral]
[Rival:Meranto|disp:Neutral>Open]

In a hybrid game, [Rival:] distinguishes AA-driven factions from Referee-controlled [NPA:] factions.

7.4 Offers and Deals ([Deal:])

Write the offer as a line of prose, put it to the Oracle, and record the deal:

Essaveth offers Meranto: passage for its couriers; Meranto delays
  Caldrath's next war-loan payment by a month
? Does Meranto accept? (Likely)
d: 2d6kh1[2,4]=4 -> Yes, but...
=> Essaveth's toll revenue must clear through Meranto houses
[Deal:Essaveth/Meranto|passage for couriers|Caldrath loan delayed
  |tolls through Meranto|status:active|since Turn 1]

When a deal breaks or ends, change its status:

[Deal:Essaveth/Meranto|status:active>broken by Meranto, Turn 3]

7.5 Standing, Secrets, Threads and the Crisis Clock

[Standing:Board|order:Meranto, Caldrath, Essaveth]
[Secret:Caldrath 2|army pay three months in arrears|status:rumor]
[Secret:Caldrath 2|status:rumor>confirmed]
[Thread:The herald's warning|Open]
[Clock:Crisis 1/4]
[Clock:Crisis+1]
=> Blood at the passes [E:Escalation: Blood at the Passes]
  • [Standing:] lists every faction from Dominant to Exposed. Restate the whole order each turn; the new order: replaces the old.
  • [Secret:] is named for the faction and the table number. Its status is private, public, rumor or confirmed.
  • [Thread:] keeps the numbered list of open hooks the solo rules roll on.
  • The Crisis Clock is an ordinary [Clock:]. When it reaches an Escalation, mark the event.

8. Best Practices

Do write the full three-part argument before recording the leverage grade. The grade follows from the argument, not the other way around.

Don’t record a leverage grade and then construct an argument to justify it. The argument is what gets adjudicated.

Do log NPA and AA actions with the same @(Name) structure as player faction actions, including the full argument.

Don’t log faction actions as bare outcomes: @(Caldrath) moves army. Without the argument, the log is not traceable.

Do keep the verdict on the d: line and the story in the => lines. The verdict says how well it went; the consequences say what that looks like.

Do let the consequences be proportionate and leave a hook. Every result, success or failure, should give at least one other faction something to respond to.

Don’t write outcomes that close the fiction: => Caldrath is defeated. OSG ends after a fixed number of turns, not when one faction is eliminated.

Do tick down [Bon:] tags at the moment of spend, inside the leverage argument where they appear.

Don’t track bonuses separately from the argument. The spend is part of the case for why the action should succeed.

Do write the Report block in the voice of the public record: what all factions know. Keep private outcomes out of it.

Don’t put private intelligence or secret alliance details in the Report block. Log them in => lines, not in the public summary.

Do correct mistakes with a (retcon: …) note after the original line. Never rewrite the log silently.

10. FAQ

Q: Does every submitted action need to be logged in full? A: Yes, always, but compact form is fine for fast play. act/out/lev can each be a single line. What matters is that all three are present. The leverage line is what gets graded; without it, the adjudication has no record.

Q: How do I log an Unopposed action? A: Write the @(Name) block normally, then record the rule instead of a roll:

@(Meranto)
  act: Establish a courier network across the eastern provinces
  out: Ensure private message delivery regardless of road conditions
  lev: Existing agent network; no competing faction present
d: Unopposed -> Success
=> The network is running by the end of the month
[Fac:Meranto|pos:+eastern courier network]

Q: How do I handle a faction that drops out mid-game? A: Convert it to an NPA. Add a behavior: category to its tag and note the transition:

[NPA:Essaveth|pos:occupied|behavior:passive; holds position]
(note: Essaveth player absent from Turn 4; run as an NPA from Turn 4)

Q: Can I use Factionlog for a game I’m running as Referee, not playing in? A: Yes. That is the primary use case. All @(Name) blocks log submitted actions as the Referee received them. The Referee’s own reasoning is recorded in the grade on the d: line and in the => lines.

Q: Does Factionlog work with any OSG scenario? A: Yes. The notation is system-agnostic within the OSG framework: it assumes the three-part action structure, the 2d6kh1/2d6kl1 mechanic, and the turn/report cycle. Scenario-specific mechanics (spendable bonuses, NPAs, maps) are all optional layers.

Q: How does Factionlog relate to Lonelog add-ons? A: Factionlog is a fork, not an add-on. It replaces the solo character-action model entirely. Lonelog add-ons (Combat, Dungeon Crawling, Resource Tracking) are not designed for faction-scale play and are not compatible with Factionlog without adaptation.

Q: My logs use the Factionlog 0.2 forms. Are they still valid? A: Yes. Old logs stay readable; Appendix A lists each older form with its current equivalent.
